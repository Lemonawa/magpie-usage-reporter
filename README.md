# Magpie 用量上报插件 v0.1.1

给 Windows 和 Mac 各装一份，将本机 Magpie 已完成的请求统计上报到 VPS。主体是同一份 JavaScript，没有第三方包依赖，不需要自己另外安装 Node；运行时由 Magpie 的 Bun 插件宿主提供。

独立社区插件，可从 GitHub 安装，未收录到官方插件市场。已做隔离模拟验证，尚未在用户的真实设备和 VPS 上完成端到端安装验收。

## 工作方式

本机 `usage.jsonl` → 持久待传队列 → Tailscale → VPS `POST /v1/magpie/usage/requests`。

默认每 2 秒轮询一次，按**请求完成并落盘**上报，不是逐 token 推送。每批 200 条，队列最多 1000 条，剩余记录保留在原日志等待读取；失败指数退避，最长间隔 60 秒，HTTP 超时 10 秒。电脑睡眠、Tailscale 离线时不会承诺实时；恢复后继续。

- 本地供应商需明确填写允许列表，默认只有 `codex`。即使列入允许列表，Remote Magpie 也会排除。
- 排除已上报记录、其他设备的同步记录、另一台 Magpie 转来的记录和已交给后续候选的尝试。
- 保留模型、时间、token 分类、推理 token、耗时、HTTP 状态、reasoning effort。不会上报会话 ID、账号邮箱、错误原文、提示词和回复。
- 已知费用（包括真实的 0）原样保留；原始日志没有费用时不发送 `cost`，由 VPS 的 Magpie 计价。因此订阅请求上的美元数可能是 API 等效估算，不等于实际 Plus 支出。
- 每台设备生成独立 ID，再为每条记录生成稳定 `rid`；接收端依靠原生接口持久去重。重新补传、网络断开和重启不应使同一记录重复累加。
- 不同步供应商、登录凭据、Agent 接线或模型选择。插件也不修改 Magpie 主程序。

## GUI 安装与配置

以下是本插件实现的操作入口；尚未在真实桌面窗口做点击验收。

1. Magpie → **插件 → 添加插件**，填写以下 GitHub 安装源：

   ```text
   github:Lemonawa/magpie-usage-reporter
   ```

   点击添加，等待 Magpie 安装。若之前添加过旧的本地文件夹版本，先将旧版本禁用或移除；本地统计进度保存在 Magpie 配置目录，不在插件安装包里。
2. 安装完成后，侧栏会出现 **用量上报** 页面。Windows 和 Mac 都使用同一个 GitHub 安装源。

3. 先在本机 Magpie 的配置目录下创建 `usage-reporter/credentials.json`，内容为：

   ```json
   {"token":"这里填写 VPS 网关密钥"}
   ```

   Windows 默认目录是 `%USERPROFILE%\.config\magpie`。Mac 通常是 `~/.config/magpie`，设置过 `XDG_CONFIG_HOME` 时以实际目录为准。文件由当前用户保管，不放到插件包或公开仓库，不使用管理面板 Web Key。

   原生上报接口拒绝受预算、模型或账号限制的 gateway key。应使用专门生成的、能调用此接口的网关密钥；这不是一个仅能上报的权限类型，不能向不受信任的人分发。

4. 侧栏 **插件 → 用量上报**，填写：
   - VPS 网关地址：`http://<VPS 的 Tailscale 地址>:3425`，两台设备都通过 Tailscale 访问。
   - 本地供应商 ID：首次填 `codex`；其他直连供应商核实后再加入。不要把 VPS 的 Remote provider 当成本地供应商。
   - 轮询间隔：默认 `2000` 毫秒。
   - 首次补传：需要历史记录就勾选；只采集启用后的记录就取消。
   - 勾选启用，点击**保存配置**。
5. 打开一次 **插件 → 已安装**，让 Magpie 加载后端。插件宿主本身是按需启动，不是独立系统服务。宿主正在运行时不需要保持插件页面打开；重启 Magpie 后如果宿主尚未启动，先打开该页面或使用本机其他后端插件以启动宿主。
6. Mac 做同样配置，使用它本机自己的配置目录和凭据文件。**不要复制 Windows 的 `usage-reporter/identity.json`、state.json 或 run.lock 到 Mac。**

## 查看与控制

- **VPS：用量 → 请求 → 来源选择“上报”**，查看传入记录与汇总。现有接收接口没有 `computer` 字段，因此这些记录不进入原生“计算机”筛选；本插件也不伪造 Agent 或供应商名称来充当设备字段。设备 ID 在上报的 `rid` 中，供诊断。
- **本机：插件 → 用量上报**，修改配置或关闭上报。
- **重新补传全部历史**按钮会保存一次新的补传指令，并启用上报；之后打开“插件 → 已安装”。已传记录由 VPS 去重。
- 精确的运行情况在本机配置目录的 `usage-reporter/status.json`，包括上次成功时间、待传、已接受、重复、忽略、异常数量及错误分类。插件页面目前没有读取任意后端状态的桥，不能展示实时状态，不能把“配置已保存”当成“上报已成功”。
- 凭据缺失、接收端拒绝、回执格式异常时保留待传队列，状态文件会显示问题。不会把凭据写入状态或日志。
- 损坏的记录仅在 `invalid.jsonl` 留位置、哈希和时间，不复制原始内容；异常记录不会阻塞后续正常记录，请检查 invalid 计数。
- 手动关闭或换配置后，退休宿主停止上报，新宿主等待并取得单实例锁。宿主突然退出时，下次启动会识别已退出进程留下的锁。

## 更新与修补

GitHub 安装默认追踪仓库默认分支。Magpie 检查到新提交后，在 **插件 → 已安装** 显示更新，点击对应插件的**更新**。无需手动覆盖文件夹，更新不会删除独立保存的凭据、设备 ID 和待传队列。设置、增量进度和数据文件也不会上传到 GitHub。

`CHANGELOG.md` 记录版本变化；GitHub Releases 提供有版本号的发布说明。需要固定版本时可使用 `github:Lemonawa/magpie-usage-reporter#v0.1.1`，固定版本不会自动跟随默认分支。

本地开发时也可将仓库文件夹通过“添加插件”加载；修改后禁用再启用。文件夹安装不提供 GitHub 更新提示。

## 已知边界

1. 仅采集本机 Magpie 已写入 `usage.jsonl` 的记录。绕过本地 Magpie、只存在于 Agent 原生会话文件的调用不在第一版范围内。
2. 无请求/响应/路由 ID 的旧记录使用字段指纹；完全相同的字段和时间会被视作同一记录。不宣称能区别没有独立标识的两次完全相同调用。
3. 不自动扫描被外部工具轮转走的旧日志。常规追加与新日志切换有测试；轮转前尚未读取、且已经不在 `usage.jsonl` 中的内容不会自动发现。不要在补传期间删除或轮转源日志。
4. 不能覆盖接收端的已上报旧记录；固定 rid 的重复上报会跳过。后续修订成本或 token 不会自动更新已接收的历史。
5. 后端采用 Magpie 支持的服务端入口，但后台 timer 没有专用生命周期 API，依赖宿主存活；不是后台系统服务。已对真实 `host.js` 做模拟，不等于完整桌面发布版验收。
6. 在 Windows Node.js、Linux Bun 上完成测试；尚未在 macOS 实机运行。代码不依赖 Windows 路径，但不能把模拟双设备测试称作 Mac 实机验证。

## 复现验证

Windows / 已装 Node：

```sh
node --test test/reporter.test.mjs
```

Bun：

```sh
bun test test/reporter.test.mjs
```

用 Magpie 实际插件宿主（不使用真实配置）：

```sh
python3 test/host.integration.py /path/to/bun /path/to/magpie/internal/plugin/host.js
```

测试只使用临时目录、虚构记录和本机 HTTP 接收端，无真实账号、网关凭据或上游 API 调用。
